## 今すぐ実行

**依頼: $ARGUMENTS**

AI に「スライドを作って」とだけ頼むと、色・文字サイズ・余白・HTML が毎回ばらつく。人間が決めた仕組み（ルール・型・検証）の中で AI が手を動かすと品質が安定する。核になる考え方は4つ。

1. **スタイルはルールとして決めてある。** 「なんとなく良い感じ」で色や余白を足さない
2. **レイアウトは型から選ぶ。** 毎回オリジナルのレイアウトを作らない
3. **コードが正しくても見た目が正しいとは限らない。** 必ず画像に書き出して目で確認する
4. **中身はユーザー本人の言葉。** Claude は構造と見た目を担当し、主張を勝手に足さない

以下、`<SKILL_DIR>` はこの SKILL.md があるディレクトリを指す。

---

## 最初に読むもの（毎回）

1. **テーマ CSS** — プロジェクトの `slides/themes/career.css`。無ければ `<SKILL_DIR>/assets/career.css` を `slides/themes/career.css` にコピーして使う（コピーしてよいかユーザーに確認）。先頭コメントがデザイン仕様の正本
2. `<SKILL_DIR>/references/style-guide.md` — 書き方のルール
3. `<SKILL_DIR>/references/layouts.md` — レイアウト型カタログ（動くコード付き）

カタログに無い見た目が必要になったら、スライドに直接 HTML/CSS を書かない。テーマ CSS に型を追加し、`layouts.md` にも追記してから使う（追加前にユーザーに確認）。

## モードの判定

| 依頼 | モード |
|---|---|
| 新しく作りたい | A. 新規作成 |
| 既存スライドを整えて・型を揃えて | B. スタイル整形 |
| はみ出し・崩れを直して | C. レイアウト修正 |

### A. 新規作成

1. **目的を確認する。** 誰に・何分で・発表用か配布用か・材料はどこか（メモやノートのファイル）。分からないことは1つずつ聞く
2. **過去スライドを探す。** `slides/` を Grep し、再利用できる枚や構成があれば提示する
3. **構成案を出す。** 1枚1メッセージで、各枚のメッセージ（1行）と使う型だけを並べた表にしてユーザーに確認する。本文はまだ書かない
4. **書く。** ファイル名は `slides/YYYY-MM-DD_タイトル.md`。冒頭の HTML コメントに「用途・下書きであること・材料の出典」を書く。型はカタログから選ぶ
5. **目で確認する**（後述の検証ループ）
6. **報告する。** 本人の言葉で直すべき箇所（Claude が補った言い回し）を明示する

発表用と配布用の両方が要るなら、発表用を先に作り、同じ構成で `class: handout` を付けた `_配布用.md` を作る。

### B. スタイル整形

1. 対象範囲を読み、各枚について「伝えたいメッセージ」と「今の型」を一覧にする
2. メッセージに合う型を `layouts.md` の選び方表から選び直す
3. style-guide のルール違反（色の使いすぎ、同じ型が3枚続く、項目過多など）を直す
4. 文言の意味は変えない。言い回しを変える場合は変更点を報告する
5. 検証ループで確認

### C. レイアウト修正

検証ループを回し、`style-guide.md` の「崩れの定石」に沿って直す。

## 検証ループ（必須）

Marp CLI で PNG に書き出し、Read ツールで画像を見る。

```bash
# 書き出し（初回は npx が @marp-team/marp-cli を取得する）
OUT="$(mktemp -d)"
npx -y @marp-team/marp-cli@latest "slides/対象.md" \
  --theme-set slides/themes/career.css --html --images png -o "$OUT/slide.png"
ls "$OUT"
```

- `slide.001.png`, `slide.002.png` … ができる。対象範囲の枚だけ Read で確認する
- 見るポイント: 下端のはみ出し・ページ番号やフッターとの重なり・文字の折り返しで崩れた行・カードの高さの不揃い・空きすぎ
- 直したら同じ枚を書き出し直して再確認。崩れが無くなるまで繰り返す
- 書き出し先は一時ディレクトリにし、プロジェクトに PNG を残さない
- npx が使えない・失敗した場合は、その旨を報告し、VS Code の Marp プレビューで確認してもらう

## 終わりに

- 何枚作った／直したか、目で確認した枚、確認できなかった枚を報告する
- 新しい型を足した・ルールを変えた場合はテーマ CSS の先頭コメントと references を更新する
